# aldente CLI

User documentation. Every command accepts `--json`, which wraps the result in the envelope described by `aldente schema envelope`. `TARGET` is a local directory (its git repository root is used) or a git URL: `https://host/owner/name`, `ssh://[user@]host[:port]/owner/name` or `git@host:owner/name`. URLs are cloned with depth 1 into `<cache>/repos/<host>/<owner>/<name>` with hooks, filters, submodules, user git config and non-https/ssh transports disabled; `--ref <branch|tag|commit>` picks the revision. `file://`, `ext::`, URLs starting with `-` and URLs with credentials are refused before git runs. The cache is `<user cache dir>/aldente`, or `$ALDENTE_CACHE_DIR` when set.

**Symbols** are full IDs (`clj:services/billing//billing.core/charge!`) or any suffix that starts at a whole component (`billing.core/charge!`, `charge!`; not `core/charge!`). A name matching several nodes exits `3` and lists them (`error.candidates` in JSON); no match also exits `3`. JSON output always uses full IDs. Repository strings are escaped in text output (control characters become `?`) and in each graph format.

Exit codes: `0` success, `1` internal error, `2` usage error, `3` ambiguous or unknown symbol, `4` findings at or above `--fail-on`, `5` required tool missing, `6` execution refused.

| Command | Does |
|---|---|
| `aldente doctor` | Checks that `git` (2.30.0 or newer) and `clj-kondo` (2026.10.26 or newer) are on `PATH`, that the cache directory (`<user cache dir>/aldente`) is writable, and reports the platform. Prints an install hint for anything missing or too old and exits `5` if any check fails. With `--json`, `data` is the full report (schema `doctor`), also when `ok` is false. |
| `aldente analyze [TARGET] [--no-cache]` | Builds the snapshot, or reuses the one for this exact content, and prints counts of units, files, nodes and edges by kind, blind spots by category, and every diagnostic. Needs clj-kondo 2026.10.26 or newer (exit `5` with an install hint otherwise). The envelope's `snapshot` holds the key, repository, commit and analyzer version. Whether the cache was used is printed on stderr only, so repeated runs print identical output. JSON schema `analyze`. |
| `aldente serve [TARGET] [--port N] [--no-open]` | Analyzes (or reuses the snapshot), then serves the GUI and the JSON API on `127.0.0.1` (a free port unless `--port`), prints the URL with a session token and opens the browser. Ctrl-C stops it. API requests need the token in `x-aldente-token`; requests with a foreign `Host` or `Origin` are refused. With `--json`, prints `{url, port}` (schema `serve`) once listening. |
| `aldente find <pattern> [TARGET] [--kind K]… [--limit N]` | Searches symbols, impls and namespaces (other kinds with `--kind`) whose name or ID contains `pattern`, case-insensitive; at most 50 results unless `--limit` (0 = all). JSON schema `find`. |
| `aldente show <symbol> [TARGET]` | Kind, flags, languages, location, signature, doc, and direct callers and callees (strongest certainty first) with their sites; calls that differ only by language (`.cljc`) are one entry. For a namespace or unit: what depends on it and what it depends on (rolled up, with counts, `requires` included) and what it contains. JSON schema `show`. |
| `aldente graph [TARGET] [--level unit\|namespace\|symbol] [--focus <symbol> [--depth N] [--direction out\|in\|both]] [--format text\|json\|dot\|mermaid\|graphml] [--limit 0]` | The graph at a level (default `namespace`), or the neighborhood of `--focus` within `--depth` steps (default 1). Namespace and unit levels roll edges up with counts. A whole graph above 2,000 nodes or 10,000 edges is refused unless `--limit 0`. Line style shows certainty in DOT (solid, dashed, dotted) and Mermaid (solid, dotted). JSON schema `graph`. |
| `aldente blindspots [TARGET] [--category C]…` | Blind spots (macro-generated calls, unresolved symbols, unparsed files, …) and diagnostics (skipped or unreadable files). JSON schema `blindspots`. |
| `aldente cache ls\|gc\|clear` | `ls` lists remote clones and snapshots with sizes; `gc` removes temporary files and keeps the newest 5 snapshots per repository; `clear` removes every clone, snapshot and temporary file (the cache directory itself stays). JSON schemas `cache` and `cache-removal`. |
| `aldente units [TARGET]` | Lists build units (directories with `deps.edn`, `project.clj`, `shadow-cljs.edn` or `bb.edn`), their languages, source and test roots (with the alias or profile that adds them), the service flag and the number of source files each owns, then everything the file walk skipped and why. `TARGET` defaults to `.`; a path inside a git repository means the whole repository. Build files are read as data, never run. With `--json`, `data` follows schema `units`. |
| `aldente schema [name]` | Prints the JSON Schema called `name` (`doctor`, `envelope`, `units`), or lists the names when `name` is omitted. `doctor` describes `data` only. With `--json`, `data` holds the schema or the list. |
